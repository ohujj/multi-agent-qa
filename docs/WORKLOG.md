# 작업 기록 · 2026-10-26

시간 기준: Asia/Seoul. 정확한 분 단위 시각은 남기지 않았으며 아래는 실제 작업 순서와 결과다.

## 1. 배경과 설계 변경

- 첨부 기획서를 읽고 설계 회의부터 시작했다.
- 초기 목표는 범용 멀티 에이전트 QA 플랫폼, 첫 대상은 모여였다.
- 원래 병렬·의존성·자동 협업 후보가 있었지만 사용자가 직렬 수동 실행으로 범위를 줄였다.
- 사용자가 에이전트마다 프롬프트를 주고 실행 버튼을 눌러 실행하도록 정했다.
- 새 테스트에서 에이전트 대화를 초기화하기로 했다.
- 저장소 이름을 최종 multi-agent-qa로 정했고 사용자가 GitHub Public 저장소를 만들었다.
- “구현 ㄱㄱ” 이후 개발을 시작했다.

## 2. 저장소와 구현

최초 clone 시 원격 저장소는 비어 있었다. 기존 애플리케이션 코드·테스트 체계는 없었다.

구현한 내용:

- React/Vite 한국어 대시보드, 에이전트 A~E 선택, 역할·프롬프트·계정 별칭 편집.
- 실행·일시정지·재개·중단, 전체 새 테스트.
- Manager의 단일 실행 잠금과 동시 요청 409 거부.
- 에이전트별 자식 프로세스, 독립 SDK 이력, Chromium 프로필.
- Agents SDK와 observe/browser_action/report_finding 도구.
- 공통·역할·작업 프롬프트와 초기 DOM snapshot의 입력 구성.
- SSE 이벤트, 브라우저 미리보기, 발견 사항·사용자 검증 상태.
- SQLite 기록, PNG·trace ZIP 저장, Markdown·JSON 리포트 경로.
- 로컬 Host·Origin 검사와 비밀 값 마스킹, Git 제외 규칙.
- 설치 스크립트·환경변수 템플릿·사용 README.

구현 커밋: `8e140e2 feat: add local serial multi-agent QA studio`.

## 4. 빌드·검증 결과

### 명령 확인

- 설치 당시 npm 감사 결과 취약점 0건. 현재·미래 안전성 보증은 아니다.

- npm run build 여러 차례 성공.
- 프로젝트 내부 .local/browsers 경로에 Chromium 설치 성공.

- .env·.local이 Git 제외 규칙에 포함되고 Git 추적 목록에 없는 것 확인.

### 로컬 smoke 검증

성공 로그:


## 5. 검증 중 발견해 수정한 사항

- 실행 환경마다 AppData 경로가 달라 Playwright 바이너리를 못 찾는 문제가 있어 설치·실행 기본 경로를 .local/browsers로 맞췄다.
- .local 증거 파일이 Express의 dotfile 기본 처리로 열리지 않아, 제한된 파일명 검사 후 해당 파일 응답에서 허용하도록 수정했다.
- Vite 프록시의 Host 전달과 서버 Host 검사가 충돌할 수 있어 changeOrigin을 설정했다.
- 브라우저 열기와 실행이 가까이 들어올 때 초기화가 겹치지 않도록 worker의 opening Promise를 추가했다.
- 중단/종료 시간 초과 시 SIGKILL을 사용하도록 정리했다.
- 새 테스트 전에 현재 에이전트의 입력 설정을 저장하도록 UI를 조정했다.
- 실제 키와 알려진 비밀 패턴이 설정·메시지 기록에 남는 범위를 줄였다.
- 외부 Google Fonts 의존을 제거해 외부 글꼴 요청 없이 표시되도록 했다.

이 목록은 오늘 이미 반영한 수정이다. 새 컨텍스트에서 다시 수행할 미완료 목록으로 취급하지 않는다.

## 6. 업로드·실행 환경의 제약

### GitHub

최초 push는 네트워크 실행 오류가 있었고, 접근을 허용한 뒤에도 Git 인증 도우미 실행이 실패했다. 네이티브 자격 증명 도우미를 직접 조회했을 때도 Windows 자격 증명 저장소 접근 거부로 실패했다. 실제 자격 증명 값을 출력하거나 문서에 기록하지 않았다.

로컬 커밋은 존재하나 원격 push 완료를 확인하지 못했다. 마지막 원격 main 조회에서 참조가 없었다. 다른 컨텍스트는 ZIP 또는 기존 로컬 작업 사본을 우선 사용한다.

### 로컬 서버

동일 검증 프로세스 안에서 서버·UI·브라우저 연결은 성공했다. 서버 실행 로그가 나온 뒤 별도 실행 환경에서 localhost에 접근할 때 연결 거부/시간 초과가 발생했다. 이 때문에 사용자 호스트에서 서버가 계속 켜져 있다고 최종 보장하지 않았고 일반 터미널 실행 안내를 제공했다.

이 현상을 애플리케이션 전체 기동 실패 또는 정상 호스트 기동 보장으로 확대하지 않는다. 새 환경에서 다시 확인한다.
