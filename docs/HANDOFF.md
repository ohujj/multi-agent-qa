# 다른 컨텍스트에서 이어가기

작성일: 2026-10-26 (Asia/Seoul)
구현 기준: `8e140e2`
문서 작성 이후의 HEAD와 수정 상태는 새 환경에서 `git log`, `git status`로 다시 확인한다.

## 지금 상태를 한 문장으로

5명의 독립 에이전트를 사용자가 한 명씩 직접 실행하는 로컬 QA MVP를 구현하고 모의 테스트까지 마쳤다. **실제 API·모여 로그인/업무 흐름 검증과 GitHub push는 완료하지 못했다.**

## 먼저 읽을 순서

1. [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md): 왜 시작했고 어떤 요구로 좁혔는지.
2. [ARCHITECTURE.md](ARCHITECTURE.md): 현재 구성·코드·API·데이터·제어.
3. [PROMPTS.md](PROMPTS.md): 실제 SDK 입력 구조와 수동 협업 예시.
4. [SECURITY.md](SECURITY.md): 키 관리의 현재 상태와 제안.
5. [WORKLOG.md](WORKLOG.md): 오늘 구현·검증·실패·미검증 기록.
6. [NEXT_CONTEXT_PROMPT.md](NEXT_CONTEXT_PROMPT.md): 새 대화에 복사할 프롬프트.

문서와 소스가 다르면 실행 동작은 소스를 확인한다. 사용자 요구사항을 바꿔야 하는 경우 최신 사용자 지시와 합의된 범위를 먼저 확인한다.

## 저장소·배포 상태

- 대상 저장소: https://github.com/ohujj/multi-agent-qa
- 사용자가 Public으로 생성했다.
- 최초 확인 시 원격은 빈 저장소였다.
- 로컬 구현 커밋은 `8e140e2`다.
- push가 Git 인증 도우미 오류와 Windows 자격 증명 저장소 접근 거부로 실패했다.
- 마지막 확인에서 원격 main 참조가 확인되지 않았다. **GitHub에서 clone만 하면 최신 소스를 얻는다고 가정하지 않는다.**
- 이번 인계 문서와 최신 소스를 포함한 ZIP 또는 기존 로컬 작업 사본을 사용한다.
- 이 문서화 작업에서는 인증을 다시 시도하거나 실제 키를 읽지 않는다. GitHub 반영 여부를 완료로 표시하지 않는다.

정상 사용자 터미널에서 인증이 가능한 경우:

```powershell
git status --short
git log -3 --oneline
git remote -v
git push -u origin main
```

다른 PC에서 소스 ZIP을 사용하는 경우 원격 저장소를 clone한 작업 사본에 압축을 푼 소스를 반영하고, 변경 내용을 확인해 새 커밋으로 올릴 수 있다. 기존 .git을 덮어쓰거나 저장소를 무조건 재초기화하지 않는다.

인증이 실패했다고 API 키나 GitHub 토큰을 채팅에 요청하지 않는다. OpenAI 키와 GitHub 인증은 별개다.

## 새 환경에서 시작

소스 ZIP을 풀거나 코드가 들어 있는 작업 사본을 연다. 제공한 소스 ZIP은 git archive 결과이므로 .git 이력을 포함하지 않는다. 기존 로컬 작업 사본에는 커밋이 있다. 실제 Git 상태를 먼저 확인한다.

```powershell
node --version
npm.cmd ci
npm.cmd run browser:install
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
notepad .env
npm.cmd run check
npm.cmd run build
npm.cmd start
```

- Node 22.16 이상 필요. 오늘 사용한 버전은 22.17.0.
- 실제 키·모델은 사용자가 .env에 직접 입력한다.
- 기본 접속은 http://127.0.0.1:4310.
- 개발은 `npm.cmd run dev`, UI는 http://127.0.0.1:5173.
- 새 환경에서 .env·node_modules·dist·.local이 없다고 오류로 판단하지 않는다. 비밀·실행 데이터·설치 결과는 의도적으로 제외한다.
- API 키와 모델이 없으면 AI 실행 버튼이 비활성화되는 것이 정상이다.
- API 사용 비용은 Codex 구독 권한과 별개로 확인해야 한다.

## 옮겨야 할 것

**일반 인계에는 소스와 문서만** 옮긴다. package-lock.json과 .env.example을 포함한다. 비밀 값은 포함하지 않는다.

.env, 브라우저 프로필, SQLite, 실제 화면 증거, trace를 새 컨텍스트에 첨부하지 않는다. 기존 실행 데이터를 옮겨야 한다면 별도 요구·접근 범위·민감 정보 확인을 거쳐야 한다. 이번 문서화·소스 ZIP에는 포함하지 않는다.

## 다음 작업 우선순위 · 제안

사용자가 새 컨텍스트에서 다른 작업을 지시하면 그 지시를 우선한다. 아래는 완료되지 않은 사항을 기준으로 한 추천 순서다.

1. 실제 GitHub 반영 여부와 로컬 작업 사본을 확인한다.
2. 사용자 PC 일반 터미널에서 빌드·브라우저·대시보드를 기동한다.
3. 사용자가 로컬에서 키와 모델을 설정하고 승인된 테스트 계정으로 로그인한다.
4. 먼저 읽기 중심의 작은 실제 AI 작업으로 도구 호출과 모델 호환성을 확인한다.
5. 승인된 데이터 범위에서 같은 에이전트 재실행, A→B→A, 생성·참여·참여자 확인을 검증한다.
6. 실제 API 응답 대기 중 일시정지·중단, 브라우저 종료·OAuth·실패 복구를 확인한다.
7. 키 관리 강화가 요청되면 SECURITY.md의 환경변수 최소 전달·브라우저 상속 점검·OS 저장소 연동을 검토한다.

병렬 실행·DAG·자동 공유를 위 항목과 묶어 임의로 추가하지 않는다.

## 작업 규칙 인계

- 이 프로젝트는 TypeScript/Node.js/React 애플리케이션이다. Java/Spring 구조로 가정하지 않는다.
- 변경 전 연관 API·Manager·Worker·브라우저·공유 타입·UI 경로를 읽는다.
- 수동 직렬 실행, 역할 비고정, 새 테스트 대화 초기화의 기존 동작을 유지한다.
- 같은 테스트의 대화와 저장 로그인 프로필을 혼동하지 않는다.
- AI가 성공했다고 말하는 것과 실제 원격 상태가 성공인 것을 구분한다.
- 쓰기 요청 중단 시 원격 반영 여부가 불명일 수 있다. 자동 재시도로 중복 생성하지 않는다.
- 실제 키·비밀번호·토큰을 소스·로그·보고서·프롬프트에 넣지 않는다.
- 문서의 후속 개선 제안을 이미 구현된 기능이나 사용자 확정 요구로 바꾸지 않는다.
- 실행 결과를 보고할 때 모의 검증과 실제 서비스 검증을 구분한다.
