# 텍스트 중심 QA 고도화 · 2026-10-26

이 문서가 현재 보고·종료·캡처 동작의 기준이다. WORKLOG의 초기 구현 기록은 당시 상태를 설명한다.

## 사용자 요구의 최신 변경

사이트 링크와 프롬프트를 주고 AI가 탐색하게 하되, 사용자는 화면 대신 **관찰·판단 요약·의심·검증을 텍스트로 보고** 싶다고 했다. DOM 기반 탐색을 유지하고 캡처는 선택 사항으로 바꾸기로 했다. 이전 점검의 잔존 문제를 먼저 수정하라는 구현 지시를 받았다.

기존 5명·수동 직렬 실행·새 테스트 대화 초기화는 유지한다. 모델의 내부 사고 과정 원문을 공개하는 기능은 아니다.

## 현재 구현

- 활동 유형: goal/observation/decision/action/result/suspicion/verification/feedback.
- source=system은 실제 실행 기록, source=agent는 AI의 사용자용 요약이다.
- browser_action은 intent를 요구한다. 행동 목적·관찰 근거의 짧은 요약이다.
- report_progress로 추가 관찰·판단 요약·의심·검증 결과를 보고한다.
- 의심은 미확인으로 구분한다. AI가 독립적으로 재현을 인증하지 않는다.
- UI의 실시간 활동 패널은 유형별 필터와 출처를 표시한다.
- 활동과 결과는 SQLite·JSON·Markdown에도 남긴다.
- DOM 기반이므로 시각적 결함·canvas·복잡한 iframe/팝업 자동 탐색은 보장하지 않는다.

## 종료 상태

```text
실행 → running → 작업 완료 → waiting(종료 대기)
                   │                 │
                   └── 종료·피드백 ──┘
                              ↓
                         summarizing
                              ↓
                         completed
```

waiting에서는 AI가 더 행동하거나 호출을 반복하지 않는다. 다른 에이전트 실행 또는 같은 에이전트 추가 지시를 사용자가 선택할 수 있다. 최종 피드백 요청은 다시 직렬 잠금을 획득한다.

종료·피드백 요청 시 새 모델/도구 동작을 막고, 진행 중 SDK 요청을 취소한다. 이미 시작된 브라우저 액션은 결과가 불명일 수 있어 종료를 기다려 기록한다. 이후 브라우저를 닫고 **조작 도구 없는 별도 모델 요청**으로 보고서를 만든다.

기록은 수행 요청·관찰된 결과·미확인 의심·발견 사항·재현 절차·후속 확인을 구분한다. 정리 요청은 실제 OpenAI API 비용이 발생할 수 있다.

요약 실패/시간 초과는 기록 기반 피드백으로 대체한다. 부모의 전체 종료 제한에 도달해 worker가 강제 종료돼도 저장된 기록 기반 대체물을 남긴다. 실제 확인하지 않은 일을 완료했다고 꾸미지 않는다.

긴급중단은 별개다. 바로 API 취소·worker 종료를 요청하고 다음 실행의 잠금은 worker 종료 후 해제한다. 이후 기록을 사용자가 따로 정리할 수 있다.

## 스크린샷 정책

captureMode는 off/findings/actions다. 기존 DB에서 값이 없으면 off로 초기화한다.

| 모드 | PNG | trace |
| --- | --- | --- |
| off · 기본 | 생성 안 함 | 생성 안 함 |
| findings | 발견 기록·액션 오류 시만 | 생성 안 함 |
| actions | 액션 후 및 발견/오류 | 실행 추적 ZIP |

이미지를 모델에 보내지 않는다. 꺼짐으로 바꿔도 기존 파일을 삭제하지 않는다. 텍스트 기록에도 개인정보가 포함될 수 있으므로 허용된 계정·데이터만 사용한다.

## 점검 결함의 수정

| 점검 ID | 수정 |
| --- | --- |
| R1 | 순서 Locator 대신 관찰 노드에 묶인 handle, label/type/href/form/행 의미 재검사. 분리·변경 시 재관찰 |
| R2 | 클릭과 Enter/Space에서 연관 form·submit·목적지 검사. 위험 form의 암묵 제출 차단 |
| R3 | 정규화된 입력 type을 관찰·조작 시 모두 확인 |
| R4 | 최초 탐색 실패 시 context 정리. 다시 열기로 실제 재탐색 |
| R5 | updated_at 동률이면 rowid 내림차순으로 새 테스트 선택. 스키마 변경 없음 |
| R6 | worker 환경 허용 목록, worker의 .env 재로딩 금지, Chromium의 API 키 제외 |
| R7 | 지원하지 않는 URL·깨진 JSON은 400, 크기 초과는 413 |
| R8 | 28979ad의 원격 반영 완료를 README·인계 문서에 반영 |

라벨·form 검사만으로 임의 웹사이트의 모든 JavaScript 부작용을 차단할 수는 없다. 테스트 환경과 허용 데이터 범위를 지킨다.

## 검증 결과와 한계

로컬 실제 Chromium·별도 SQLite·모의 Responses 서버로 검증했다. 실제 API·모여 데이터는 사용하지 않았다.

브라우저/저장 회귀:
- DOM 앞쪽에 버튼 삽입 후 원래 노드 클릭, 의미 변경 거부.
- 위험 Enter 차단과 안전한 form의 Enter 허용.
- 대문자 PASSWORD 제외 및 실행 직전 타입 변경 거부.
- 최초 연결 실패 후 새 context로 재시도.
- 동일 밀리초 저장에서 새 테스트 선택.
- Chromium의 가짜 API 키 제외, worker의 관련 없는 비밀 제외.
- off에서 PNG/trace 없음, findings에서 명시적 증거만 저장.

통합:
- 관찰·판단 요약·의심·출처와 waiting 상태.
- 종료 중 직렬 잠금, 중복 종료 거부, 브라우저 종료.
- 피드백 요청에 브라우저 도구 없음, API store=false.
- 모델 요청 도중 종료해도 최종 피드백 수신.
- 진행 중 브라우저 액션을 기다리고 늦은 결과도 정리에 포함.
- 긴급중단·실행 시간 초과·요약 실패 대체.
- JSON/Markdown, 새 테스트 초기화.
- 활동 필터·모바일 가로 넘침·UI pageerror 검사.

실제 모델의 요약 준수·탐색 품질·비용, 소셜 로그인, 모여 업무 흐름은 별도 검증이 필요하다.
