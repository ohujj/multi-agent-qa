기준일: 2026-10-26 (Asia/Seoul)
초기 구현 기준 커밋: `8e140e2`
저장소: https://github.com/ohujj/multi-agent-qa (Public, 사용자가 생성)
첫 테스트 대상: https://moyeo-web.vercel.app/login

이 문서는 대화에서 확정된 요구와 실제 구현을 구분해 다음 작업자에게 전달한다. 문서에 “제안”으로 표시한 항목은 구현 지시나 확정 정책이 아니다.

## 최신 요구 · 텍스트 보고 중심

사용자가 화면 대신 관찰·판단 요약·의심·검증을 텍스트로 보고 싶다고 했고, DOM 탐색과 선택적 캡처를 채택했다. 기본 PNG/trace는 꺼짐이다. 종료·피드백은 조작 종료 후 별도 정리 요청이며 긴급중단과 다르다. 이전 점검 문제를 먼저 수정하라는 승인에 따라 R1~R8을 수정했다. 자세한 현재 동작은 [TEXT_REPORTING.md](TEXT_REPORTING.md)를 읽는다. 아래 초기 기획·선택 이유는 이 변경 이력과 함께 해석한다.

## 1. 처음 만들고자 했던 것

여러 AI가 실제 사용자처럼 브라우저를 조작하며 기능 결함, 보안 의심, UX 불편, 서비스 개선 아이디어를 발견하는 로컬 QA 플랫폼이다. 모여를 첫 대상으로 삼지만 모여 전용으로 고정하지 않는다.

원래 요청에는 독립 에이전트 5명, 병렬 실행, 에이전트 간 데이터 공유, DAG 또는 이벤트 기반 의존성, 자연어 시나리오 편집, 실시간 관찰·제어·통합 리포트, 향후 모바일 앱 확장이 포함됐다. 처음에는 구현하지 않고 설계 회의만 진행하라는 요청이 있었다.

이후 사용자가 초기 범위를 아래처럼 좁혔고, “구현 ㄱㄱ”로 구현을 승인했다. **원래 병렬 설계를 현재 요구사항으로 되살리지 않는다.**

## 3. 대화에서 설명하고 MVP에 반영한 동작

아래는 위 사용자 요구를 구체화한 구현 방향이다. 사용자의 발언 그대로인 것과 구분한다.

- 실행 순서는 A→B→C로 고정하지 않는다. A→B→A 등 자유롭게 선택한다.
- 다른 에이전트가 실행 중이면 실행을 거부한다. 자동 대기열은 없다.
- 계정·대화·브라우저 프로필은 에이전트별로 분리한다.
- 역할 기본값은 비워 둔다. 모임장·참여자 등 역할을 프로그램에 강제하지 않는다.
- 초대 링크 등의 정보는 사용자가 결과에서 복사해 다음 프롬프트로 전달한다.
- 같은 테스트의 같은 에이전트는 이전 대화를 이어간다.
- 새 테스트에서 브라우저를 닫고 현재 대화·결과를 초기화한다.
- 역할·프롬프트·계정 별칭·대상 설정·로그인 프로필은 재사용한다.
- 기존 테스트 기록은 로컬 DB에 남기지만 과거 테스트 조회 UI는 아직 없다.
- 로그인은 사용자가 전용 브라우저에서 직접 한다.
- 실행 상태·유형별 텍스트 보고·선택 저장 증거·발견 사항·피드백을 로컬 대시보드로 제공한다.
- Codex는 개발 도구로 사용하고, 제품 런타임은 OpenAI Agents SDK + 직접 구현한 실행 관리자다.

로그인 프로필 유지·정확한 초기화 범위는 MVP에서 채택한 동작이다. 대화 초기화와 브라우저 인증 초기화를 같은 뜻으로 해석하지 않는다.

package.json의 private: true는 npm 배포 방지 설정이다. GitHub 저장소의 Public/Private 설정과는 별개다.

## 4. 현재 UX

1. 로컬 프로그램을 시작하고 대시보드에 접속한다.
2. 테스트 대상 URL과 공통 지침을 저장한다.
3. A~E 각각의 역할과 계정 별칭을 정한다.
4. 필요한 전용 브라우저를 열어 직접 로그인한다.
5. 선택한 에이전트에 이번 작업 프롬프트를 입력하고 실행한다.
6. 유형별 활동 보고와 발견 사항을 확인하고 필요하면 선택 저장 증거를 연다.
7. 완료 후 필요한 정보를 다음 에이전트의 프롬프트로 전달하고 직접 실행한다.
8. 종료하고 피드백을 받은 뒤 결과를 내보낸다. 새 테스트에서는 대화 이력을 초기화한다.

브라우저 프로세스는 5개를 시작 시 무조건 띄우는 방식이 아니다. 5개의 에이전트 구성을 미리 만들고, 브라우저 열기 또는 실행 요청 시 해당 작업 프로세스를 생성한다.

## 5. 기술 선택과 이유

| 선택 | 이유·한계 |
| --- | --- |
| 모여와 별도 저장소 | 대상 서비스와 QA 도구를 분리, 다른 서비스에도 재사용 |
| TypeScript/Node.js | UI·실행 관리자·브라우저 도구의 타입 공유 |
| React + Vite | 로컬 대시보드에 필요한 구성. Next.js는 채택하지 않음 |
| OpenAI Agents SDK | 개별 모델·도구 실행 루프 사용. 여러 에이전트 간 직렬 제어는 직접 구현 |
| Playwright | 전용 Chromium·프로필·DOM 관찰·화면 증거·trace |
| HTTP + SSE | 명령은 HTTP, 상태 변화는 SSE. WebSocket은 미채택 |
| Node 내장 SQLite | 별도 DB 서버 없이 로컬 기록 저장 |
| 자식 프로세스 | 에이전트 실행·종료·메모리 이력 분리. OS 보안 샌드박스는 아님 |

현재 에이전트는 DOM 텍스트와 요소 참조로 행동한다. 스크린샷은 사용자 관찰·증거용이며 모델에 이미지 입력으로 넘기지 않는다.

## 6. 이번 MVP에 포함하지 않은 것

- 병렬 실행, DAG, 의존성 자동 추론, 자동 작업 대기열
- 자동 에이전트 메시지·공유 컨텍스트·초대 링크 자동 전달
- YAML/JSON 시나리오 편집·독립 시나리오 라이브러리
- 네이티브 모바일 앱 자동화
- 실시간 영상 스트리밍·원격 브라우저 제어
- 과거 테스트 조회 UI·실행 간 비교
- Windows 자격 증명 저장소 연동·자동 키 교체
- 독립적인 자동 버그 재현·보안 진단 보증
- 금액 기준의 실행 중 비용 차단

DB에 현재 역할·프롬프트가 저장되는 것과, 이름을 붙여 여러 시나리오를 관리하는 기능은 다르다.

## 7. 유지할 판단 기준

현재 합의인 수동 직렬 실행, 개별 컨텍스트, 사용자의 역할 편집, 검증 상태 구분을 먼저 지킨다. 확장 기능은 현재 구현으로 오해하지 않도록 별도 제안한다. 키·계정·세션을 문서나 대화에 복사하지 않는다. Public 저장소에 올릴 파일을 확인한다.

오늘 기능 구현과 별도로 인계 문서 작성이 요청됐다. 이 문서화 작업은 실행 로직이나 키 저장 방식을 바꾸는 승인으로 확대 해석하지 않는다.

## 근거

- 사용자 최초 첨부 기획 요청의 독립성·관찰·범용성 요구.
- 후속 대화의 직렬 실행·수동 버튼·새 테스트 초기화 결정과 구현 승인.
- `shared/types.ts`, `server/manager.ts`, `server/worker.ts`, `server/browser.ts`, `src/App.tsx`를 대조한 구현 사실.
- 검증 범위와 미완료 사항은 [HANDOFF.md](HANDOFF.md), 날짜별 기록은 [WORKLOG.md](WORKLOG.md).
