# API 키와 로컬 데이터 관리

기준일: 2026-10-26. 실제 구현과 권고안을 구분한다. 이 문서에는 실제 키·비밀번호·토큰을 넣지 않는다.

## 1. 현재 추천 방향

**전용 OpenAI 프로젝트와 키를 만들고, 초기 MVP에서는 로컬 .env 또는 실행 프로세스의 환경변수로 서버에 전달한다.**

이것은 이번 대화에서 제시한 권고다. 사용자가 키 저장소 변경 구현을 승인하거나 키를 제공한 상태는 아니다. Windows 자격 증명 저장소는 장기 개선안이며 아직 연동하지 않았다.

공식 근거:
- [OpenAI API 인증](https://developers.openai.com/api/reference/overview#authentication): 키는 클라이언트에 노출하지 않고 서버의 환경변수 또는 키 관리 서비스를 통해 로드.
- [OpenAI 운영 지침](https://developers.openai.com/api/docs/guides/production-best-practices): 코드·공개 저장소 노출 방지, 프로젝트 분리, 사용량 관리, 키 수명·교체 관리.

이 공식 지침은 이전 보안 논의에서 조회했다. 대시보드의 실제 설정 화면·권한 종류·계정별 한도 지원 여부는 해당 계정에서 다시 확인한다.

## 2. 현재 코드에서 확인한 것

| 항목 | 현재 상태 |
| --- | --- |
| 키 읽기 | config.ts에서 dotenv/config를 로드하고 process.env.OPENAI_API_KEY 사용 |
| UI 입력 | API 키 입력 UI 없음. 역할·작업 프롬프트에 키를 넣는 구조 아님 |
| 실행 조건 | API 키와 모델 ID가 모두 있어야 실행 가능 |
| Git 제외 | .env, .env.* 제외. 비밀 값 없는 .env.example만 예외 |
| 작업 프로세스 | Manager가 현재 process.env 전체를 worker에 상속 |
| SDK | worker에서 API 사용. tracingDisabled=true, traceIncludeSensitiveData=false |
| 텍스트 기록 | 알려진 API 키 문자열·일부 토큰 패턴 마스킹 |
| 브라우저 증거 | PNG에서 input/textarea/contenteditable 영역 마스킹 |
| 데이터 | DB·브라우저 프로필·증거·바이너리를 .local 아래 저장, Git 제외 |
| 서버 | 127.0.0.1 바인딩, Host·Origin 검사. 원격 다중 사용자 인증은 없음 |

**“서버에서만 사용”은 프런트엔드에 키를 제공하지 않는다는 뜻이다. 메인 서버 한 프로세스만 키를 보유한다는 뜻은 아니다.** 현재 worker들도 환경변수로 같은 키를 받는다.

Playwright 브라우저 실행 옵션에는 명시적인 환경변수 허용 목록이 없다. 브라우저 하위 프로세스까지 키가 상속되는지 보안 개선 시 확인하고, 필요 없는 환경변수는 전달하지 않는 방향을 검토해야 한다. 이번 작업에서 브라우저 프로세스의 실제 환경을 검사한 것은 아니다.

Git 제외와 마스킹은 암호화가 아니다. .env와 .local을 읽을 수 있는 다른 프로세스나 사용자를 막는 보안 경계가 아니다.

## 3. 초기 설정 절차

### 키 발급 시

1. QA 도구 전용 프로젝트를 만들거나 개발/테스트 전용 프로젝트를 사용한다.
2. 운영 서비스의 키를 재사용하지 않는다.
3. 실제로 필요한 API 기능에 한정한 권한을 설정한다. 모델 실행 성공에 필요한 권한은 실제 선택한 SDK·모델에서 검증한다.
4. 사용량 알림과 제공되는 한도 설정을 확인한다. 알림·금액 차단·속도 제한을 같은 기능으로 오해하지 않는다.
5. 만료·교체 주기를 관리한다. 계정이 지원하는 설정은 대시보드에서 확인한다.
6. 키를 사용자 본인이 로컬에서 입력한다. 채팅이나 인계 문서에 붙여넣지 않는다.

5개의 AI 역할은 5개의 OpenAI 계정 사용자를 뜻하지 않는다. 로컬 프로그램의 5개 worker가 같은 애플리케이션 전용 키를 쓰는 현재 구조다. 실제 사람 여러 명이 사용하는 서비스로 바뀌면 사용자별 권한·과금·키 관리 설계를 다시 한다.

### .env 생성

프로젝트 루트에서 실행한다. 기존 파일은 덮어쓰지 않는다.

```powershell
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
notepad .env
```

사용자 본인이 아래 항목을 채운다.

```dotenv
OPENAI_API_KEY=발급받은_키
OPENAI_MODEL=사용할_모델_ID
```

`VITE_OPENAI_API_KEY`, React 코드, browser localStorage, 계정 별칭, 에이전트 역할·프롬프트에 저장하지 않는다. VITE_로 노출하는 환경변수는 클라이언트에 포함될 수 있다.

변경 후 서버를 재시작한다. 키 문자열을 로그로 출력하거나 동작 확인을 위해 화면에 표시하지 않는다.

.env는 평문 파일이다. 본인만 접근 가능한 위치·파일 권한을 사용하고 공유 폴더·동기화·백업 범위를 확인한다. 문서에 예시로 적은 키 자리표시자를 실제 키로 치환해 저장소에 올리지 않는다.

## 4. 설정 방식 비교

| 방식 | 장점 | 한계 | 현재 상태 |
| --- | --- | --- | --- |
| 로컬 .env | 간단하고 재실행 편리 | 평문, 복사·백업·파일 권한 관리 필요 | 지원 |
| 현재 실행 프로세스 환경변수 | 소스 트리에 키 파일을 두지 않아도 됨 | 프로세스 메모리·자식 상속에 남음, 키를 직접 명령에 적으면 셸 기록 노출 가능 | 지원 |
| Windows 자격 증명 저장소·OS 암호화 연동 | 평문 .env 파일 저장을 줄일 수 있음 | 네이티브 연동·키 등록/교체/삭제 흐름과 오류 복구 필요. 같은 사용자 권한의 악성 코드로부터 절대 보호는 아님 | 미구현 제안 |
| 조직용 Secret Manager | 접근·감사·교체 중앙 관리 | 개인 로컬 MVP에는 운영 복잡도 증가 | 미구현 |
| GitHub Actions Secrets | CI 작업에 제공 가능 | 현재 로컬 서버가 자동으로 읽는 저장소가 아님 | 현재 CI 없음 |

Windows 사용자/시스템 전체에 영구 환경변수를 등록하는 것이 자동으로 더 안전한 것은 아니다. 상속 범위가 넓어질 수 있다. 셸 명령에 실제 키를 직접 써서 전달하는 예시는 인계 자료에 남기지 않는다.

## 5. 나중에 키 관리를 개선한다면

아래는 제안이며 현재 구현됐거나 사용자가 우선순위를 확정한 것으로 취급하지 않는다.

1. 키 공급자 인터페이스를 만들어 환경변수와 OS 저장소를 교체 가능하게 한다.
2. 키는 로컬 서버/필요한 worker에만 전달하고 UI·SSE·SQLite·보고서에는 넣지 않는다.
3. worker 환경변수를 허용 목록으로 좁힌다. .env의 다른 비밀까지 전부 상속하지 않는다.
4. Chromium 실행 환경에서는 API 키 및 불필요한 비밀 변수를 제거한다.
5. 자격 증명 저장소 등록·교체·삭제는 사용자가 명시적으로 수행하는 로컬 흐름으로 설계한다.
6. UI에는 ‘설정됨/미설정’과 연결 오류만 보여 준다. 키 원문을 반환하지 않는다.
7. 새 키로 최소한의 API 연결 검증 후 이전 키를 폐기한다.
8. 파일·프로세스 격리를 OS 보안 샌드박스로 홍보하지 않는다.

전용 네이티브 의존성을 추가하기 전에 Windows 지원·패키지 유지보수·설치 요구를 공식 자료로 검증한다.

## 6. 이동·Public 저장소에 포함할 것과 제외할 것

### 포함

소스, README, docs, package.json, package-lock.json, 비밀 값 없는 .env.example.

### 제외

.env, 실제 API 키·비밀번호·인증 토큰, .local 전체, 브라우저 프로필, DB, trace, 실제 서비스 증거, node_modules, 빌드 결과.

같은 사용자라도 다른 컨텍스트에 로그인 프로필을 무조건 복사하지 않는다. 가능하면 새 환경에서 다시 로그인한다. 복사가 꼭 필요하면 대상과 접근 권한을 사용자가 확인한 별도 절차로 처리한다.

검사 명령은 프로젝트 루트에서 실행한다.

```powershell
git check-ignore .env .local
git ls-files -- .env .local
git diff --cached --name-only
git diff --cached --check
```

앞의 check-ignore는 제외 규칙 확인이다. 이미 추적된 비밀 파일을 자동으로 추적 해제하지 않는다. ls-files 결과에 비밀 파일이 나오면 공개 반영 전에 처리해야 한다. 값을 출력해 확인하지 않는다.

## 7. 증거·프롬프트의 추가 데이터 범위

- 모델에는 프롬프트와 DOM 텍스트·도구 결과를 보낸다. 로컬 전용 추론이 아니다.
- 화면 본문의 개인 정보는 입력 필드 마스킹으로 모두 가려지지 않는다.
- Playwright trace는 네트워크·DOM·화면 등 민감 정보를 담을 수 있다. PNG 마스킹과 별도로 취급한다.
- API 모델의 서버 측 데이터 보존 설정을 이 프로젝트에서 별도로 검증·강제한 상태는 아니다. 민감한 테스트 전에 실제 계정·API 정책을 확인한다.
- 외부 페이지 지침은 신뢰하지 않는 데이터로 다룬다. 모델에게 제한된 도구만 제공하는 것도 함께 유지한다.
- 삭제·결제 등의 라벨 차단은 보조 수단이다. 운영 서비스에 대한 전면 보안 테스트 승인으로 해석하지 않는다.

## 8. 키가 노출됐다면

1. OpenAI 관리 화면에서 해당 키를 폐기한다.
2. 사용량과 비용을 확인한다.
3. 새 키를 발급하고 로컬 설정을 교체한다.
4. 코드·Git 이력·로그·문서·공유 ZIP 등 노출 경로를 확인한다.
5. Git 이력 재작성이나 공유 파일 삭제는 영향 범위를 확인하고 사용자 승인에 따라 처리한다.

키를 저장소에서 지우거나 .gitignore에 추가하는 것만으로 이미 노출된 키가 안전해지지 않는다.

## 확인 범위

config.ts, manager.ts, worker.ts, browser.ts, index.ts와 .gitignore를 읽어 확인했다. 실제 키를 조회·출력·생성·등록하거나 Windows 파일 권한·자격 저장소를 변경하지 않았다.
