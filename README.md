# multi-agent-qa

로컬 PC에서 독립된 AI 에이전트 5명을 **한 번에 한 명씩 직접 실행**하는 웹 서비스 QA 스튜디오입니다.

에이전트별 역할과 작업 프롬프트를 입력하고 실행 버튼을 누릅니다. A → B → A처럼 실행 순서는 자유롭고, 자동 실행·자동 대기열·에이전트 간 자동 공유는 없습니다. 첫 대상의 기본 주소는 [모여](https://moyeo-web.vercel.app/login)이며 다른 웹 서비스 URL도 설정할 수 있습니다.

## 시작하기 · Windows PowerShell

Node.js **22.16 이상**이 필요합니다. SQLite는 Node 내장 모듈을 사용하므로 Node 22에서 experimental 경고가 나올 수 있습니다.

```powershell
git clone https://github.com/ohujj/multi-agent-qa.git
cd multi-agent-qa
npm.cmd ci
npm.cmd run browser:install
Copy-Item .env.example .env
notepad .env
```

생성한 로컬 `.env`에서 아래 두 값을 설정합니다.

```dotenv
OPENAI_API_KEY=사용자의_OpenAI_API_키
OPENAI_MODEL=계정에서_사용할_수_있는_모델_ID
```

도구 호출을 지원하는 OpenAI API 모델을 사용하세요. API 호출은 별도 사용 비용이 발생할 수 있습니다. API 키는 서버에서만 읽으며 대시보드에 입력하지 않습니다. 키·모델이 없으면 브라우저 준비와 대시보드는 이용할 수 있지만 AI 실행 버튼은 비활성화됩니다.

```powershell
npm.cmd run build
npm.cmd start
```

[http://127.0.0.1:4310](http://127.0.0.1:4310)에 접속합니다. 종료는 실행한 터미널에서 Ctrl+C입니다.

개발 중에는 `npm.cmd run dev` 후 [http://127.0.0.1:5173](http://127.0.0.1:5173)에 접속합니다. 프런트엔드와 백엔드가 함께 실행됩니다.

브라우저 바이너리는 프로젝트의 `.local/browsers/`에 설치합니다. 의존성을 업데이트해 Playwright 버전이 바뀌면 `npm.cmd run browser:install`을 다시 실행하세요.

## 사용 순서

1. 테스트 설정에서 대상 URL과 공통 지침을 저장합니다.
2. A~E 각각에 역할과 계정 **별칭**을 입력합니다. 역할은 기본으로 강제하지 않습니다.
3. **전용 브라우저 열기**를 누르고 허용된 테스트 계정으로 직접 로그인합니다. 에이전트마다 다른 계정을 사용할 수 있습니다.
4. 에이전트를 선택하고 이번 작업의 프롬프트를 입력한 뒤 실행합니다.
5. 실제 Chromium 창, 액션 후 갱신되는 화면 미리보기, 실시간 활동 로그와 발견 사항을 확인합니다.
6. 완료 후 다음 에이전트를 직접 실행합니다. 필요한 초대 링크 등은 결과에서 복사해 다음 프롬프트로 전달합니다.
7. 발견 사항의 근거와 재현 절차를 확인하고, 직접 재현했다면 검증 상태를 변경합니다.
8. 발견 사항 화면에서 Markdown 또는 JSON 리포트를 내보냅니다.

브라우저를 사용자가 직접 조작하는 동안에는 AI를 일시정지하거나 실행 완료 후 작업하세요. 원격 서비스에 생성한 모임·참여 데이터는 로컬 초기화로 삭제되지 않습니다.

## 대화와 새 테스트

- 같은 테스트·같은 에이전트: 대화 이력을 이어갑니다.
- 에이전트 간: 대화·도구 이력·브라우저 프로필을 공유하지 않습니다.
- **새 테스트**: 모든 작업 프로세스와 브라우저를 종료하고, 5명의 대화·현재 결과·미리보기·상태를 초기화합니다.
- 역할·프롬프트·계정 별칭·대상 설정은 다음 테스트에서 재사용합니다.
- 로그인 프로필은 에이전트별로 유지합니다. 새 테스트는 로그아웃 또는 서비스 데이터 정리가 아닙니다.
- 이전 테스트 결과는 로컬 SQLite에 보존합니다. 이전 테스트를 불러오는 UI는 MVP에 포함하지 않았으므로 초기화 전에 리포트를 내보내세요.
- 서버 재시작 시 진행 중 작업은 중단 상태로 복구하며 자동 재실행하지 않습니다. 완료된 사용자/에이전트 대화는 복구하지만 중단된 도구 호출 체인은 재생하지 않습니다.

## 실행 제어

| 제어 | 동작 |
| --- | --- |
| 실행 | 서버가 직렬 잠금을 얻은 뒤 해당 에이전트만 시작. 동시 요청은 HTTP 409로 거부 |
| 일시정지 | 진행 중 모델 응답·브라우저 액션은 끝날 수 있음. 다음 모델 요청 또는 도구 액션 경계에서 대기 |
| 재개 | 대기 중인 실행을 이어감 |
| 중단 | 모델 취소 요청 후 해당 작업 프로세스와 브라우저 종료. 종료가 확인될 때까지 직렬 잠금 유지 |
| 시간 제한 | 기본 180초. 일시정지 시간도 포함. 초과 시 중단 |
| 최대 턴 | 기본 모델 25턴. SDK의 모델 요청 루프 한도이며 개별 클릭 수와 다름 |

이미 서비스 서버에 전달된 쓰기 요청은 중단해도 반영될 수 있습니다. 생성·가입 도중 실패했다면 실제 결과를 확인하고 다시 실행하세요. 자동 재시도나 자동 롤백은 없습니다.

`.env`의 `MAX_TURNS`, `RUN_TIMEOUT_SECONDS`, `PORT`로 제한과 포트를 바꿀 수 있습니다. 변경 후 서버를 재시작하세요. 턴·시간 제한은 비용 상한을 보장하지 않습니다.

## 구성

```text
React 대시보드
  ├─ HTTP: 프롬프트 저장 / 실행 / 일시정지 / 재개 / 중단
  └─ SSE: 상태 / 액션 로그 / 발견 사항 / 미리보기
        ↓
Node.js 실행 관리자 ─ SQLite 테스트 기록
        ↓ 직렬 잠금
에이전트별 자식 프로세스 A~E
  ├─ OpenAI Agents SDK의 독립 실행·도구 이력
  └─ Playwright 전용 Chromium 프로세스 + 전용 프로필
        ↓
설정한 웹 서비스
```

- 프런트엔드: React, TypeScript, Vite
- 서버: Express, Node SQLite
- AI 실행: OpenAI Agents SDK. SDK 트레이싱 전송은 비활성화
- 브라우저: Playwright. 관찰·이동·클릭·입력·선택·키·스크롤·발견 기록 도구
- 기록: SQLite, 로컬 PNG 스크린샷, Playwright trace ZIP
- 발견 사항: 버그 / 보안 의심 / UX / 아이디어, 심각도, 근거, 재현 절차
- 리포트: 에이전트별 결과와 전체 기록. 제목·분류 기준으로 묶되 동일 원인이라고 확정하지 않음

## 데이터와 접근 범위

이 저장소는 Public입니다. `.env`, `.local/`, 빌드·설치 결과는 Git에서 제외합니다.

| 로컬 경로 | 내용 |
| --- | --- |
| `.local/qa.sqlite` | 테스트 설정, 대화, 이벤트, 발견 기록 |
| `.local/profiles/A` ~ `E` | 계정별 로그인 프로필 |
| `.local/artifacts/` | 스크린샷과 trace ZIP |
| `.local/browsers/` | 설치한 Chromium |

대시보드와 데이터 저장은 로컬에서 동작하지만, 프롬프트·화면 텍스트·도구 결과는 모델 판단을 위해 OpenAI API로 전송됩니다. 로컬 전용 LLM 실행은 지원하지 않습니다.

- 서버는 `127.0.0.1`에만 바인딩하고 요청 Host·Origin을 검사합니다. 공개 호스팅용 서버가 아닙니다.
- 에이전트의 브라우저 도구는 설정한 URL과 같은 origin에서만 관찰·조작합니다. 외부 인증 페이지는 사람이 직접 처리합니다.
- 비밀번호·파일·숨김 입력 필드는 AI 도구에서 제외하며, 미리보기 스크린샷의 입력 필드는 가립니다.
- API 키와 알려진 토큰 패턴을 텍스트 기록에서 가립니다. 완전한 개인정보 탐지 기능은 아닙니다.
- 스크린샷의 본문, SQLite와 **Playwright trace에는 개인정보·인증 관련 데이터가 포함될 수 있습니다**. 공유 전 직접 확인하고 로컬 파일을 보호하세요.
- 임의 JavaScript·셸·직접 API 호출 도구는 에이전트에 제공하지 않습니다.
- 삭제·탈퇴·결제 등 일부 버튼을 차단하고 위험 동작 제한을 지침에 포함합니다. 라벨 기반 제한은 완전한 보안 경계가 아니므로, 허용된 테스트 계정과 환경에서 사용하세요.
- AI가 ‘재현됨’이라고 주장해도 자동으로 확정하지 않습니다. AI 기록은 최대 ‘관찰됨’이며, 사용자가 직접 검증 상태를 변경할 수 있습니다.

브라우저 프로필과 프로세스 격리는 실수로 세션을 공유하지 않기 위한 것입니다. 같은 OS 사용자 권한으로 실행되는 프로세스 사이의 악성 코드 보안 샌드박스를 제공하는 것은 아닙니다.

## 검증

```powershell
npm.cmd run check
npm.cmd run build
```

초기 빈 저장소에서 시작했으므로 기존 테스트 체계는 없었습니다. 구현 확인은 별도의 로컬 fixture와 모의 AI 응답으로 수행하며, 실제 대상 데이터에 쓰기 작업을 하지 않습니다.

수동 확인 항목:

- A 작업 도중 B를 실행할 수 없고 자동으로 대기열에 들어가지 않는지
- A·B 전용 브라우저의 로그인·쿠키·스토리지가 분리되는지
- 같은 에이전트를 재실행하면 대화를 이어가는지
- 일시정지 후 새 액션이 시작되지 않고 재개하면 이어지는지
- 중단·시간 제한·브라우저 종료 후 다시 실행할 수 있는지
- 새 테스트에서 5명의 대화가 초기화되고 로그인 프로필은 유지되는지
- 발견 사항·스크린샷·검증 상태·Markdown/JSON 내보내기가 동작하는지

실제 모델의 탐색 품질, 계정별 모델 사용 권한, 모여의 로그인 및 업무 흐름은 사용자의 API 설정과 테스트 계정으로 추가 확인해야 합니다. AI 실행 결과는 결정적인 E2E 회귀 테스트나 전문 보안 진단을 대체하지 않습니다.

## MVP의 경계

자동 병렬 실행, DAG, 에이전트 간 자동 메시지, 네이티브 모바일 앱, 실시간 영상 전송, 실행 간 비교, 과거 테스트 조회 UI는 포함하지 않습니다. 모바일 폭의 웹 화면은 대시보드에서 사용할 수 있지만 실제 모바일 앱 자동화는 별도 단계입니다.
